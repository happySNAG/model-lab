# Configuration, version 2

A version 2 file is a JSON object with `"version": 2`.

| key              | type                         | meaning                                             |
|------------------|------------------------------|-----------------------------------------------------|
| `name`           | string                       | the service's name. Required.                       |
| `region`         | string                       | where it runs, e.g. `"eu-west"`.                    |
| `timeoutSeconds` | whole number                 | how long one deploy step may take.                  |
| `color`          | `"auto"`, `"always"`, `"never"` | whether shipit's output uses colour.            |
| `deploy`         | object                       | how a new version replaces the old one.             |
| `notify`         | object                       | who hears about a deploy.                           |

## `deploy`

| key         | type                                   | meaning                                       |
|-------------|----------------------------------------|-----------------------------------------------|
| `strategy`  | `"rolling"`, `"blueGreen"`, `"recreate"` | how instances are replaced.                 |
| `maxSurge`  | whole number                           | extra instances allowed during a rollout.     |

## `notify`

| key        | type                         | meaning                                                   |
|------------|------------------------------|-----------------------------------------------------------|
| `channels` | list of `{ kind, target }`   | where to announce a deploy. `kind` is `"slack"` for now.  |

Plugins, and anything else shipit itself does not read, may add their own keys at any level. shipit
passes the whole configuration to every plugin it loads, so a plugin's keys have to be there when it
looks for them.
